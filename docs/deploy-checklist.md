# デプロイ前チェックリスト

公開（デプロイ）前に必ず全項目を確認する。根拠は設計書§7（法務セーフ設計）と
検証レポート（koosai-club-review-deploy-check-2026-10-27.md）の条件1〜6。
「未決」のまま公開してはいけない項目には ★ を付けた。

## 1. 法務・表示（ステマ規制 / 景表法）

- [ ] 全ページのヘッダー直下に PR 表記が表示されている（PrNotice コンポーネント）。
      末尾だけ・小さい文字・薄い色になっていないこと
- [ ] 紹介報酬の対象リンク（kind='affiliate'）の近くに「PR」と明記されている
- [ ] 順位が採点式のみで決まることが /method と /about に明記されている。
      契約の有無で順位を操作する実装・運用になっていないこと
- [ ] 口コミの自作自演・対価を伏せた依頼投稿をしない運用ルールが
      /method と /about に明記され、運用担当に共有されている
- [ ] 編集部記事は「編集部調査」と明示し、体験談の体裁（一人称の利用演出）を
      取っていない
- [ ] 性的関係の成立をうたう表現・煽り表現（「大人の関係」「お手当相場」等）が
      サイト内（タイトル・本文・メタ情報）に無い

## 2. サイト設計（出会い系サイト規制法との距離）

- [ ] サイトが「情報掲載のみ」で、仲介機能を持っていない
- [ ] 利用者同士が連絡を取り合う機能（DM・連絡先交換・相互コメント等）が無い
- [ ] 口コミは「投稿 → 承認 → 表示」の一方向のみで、自動公開になっていない
- [ ] 掲載対象は関係条例の届出等が確認できたものに限る運用になっている
      （確認できない対象は is_published=false のまま）

## 3. 口コミ運用

- [ ] 承認キュー（status='pending')の確認担当と頻度が決まっている
- [ ] 承認/不承認の基準が /method で公開されているものと一致している
- [ ] 個人情報が混入した投稿を不承認にする手順がある
- [ ] ダミー口コミ・サンプル口コミが DB に入っていない（seed は評価軸のみ）
- [ ] スパム対策（ハニーポット＋CAPTCHA）の状態を確認した
      ★ CAPTCHA（Turnstile等）の導入可否は未決。本実装で判断する

## 4. 情報の鮮度

- [ ] 各 items に last_checked_at が設定され、詳細ページに最終確認日が出ている
- [ ] 確認作業の履歴を check_log に残す運用になっている
- [ ] 月1〜2回のデータ棚卸し（料金改定チェック）の担当・周期が決まっている
- [ ] 非公開の金額を null のまま「非公開」表示にし、推測で埋めていない

## 5. ホスティング・インフラ

- [ ] ★ ホスティングが確定している（未決: Vercel Pro / Cloudflare Pages 等）。
      無料枠で「商用不可」のプランのまま収益化リンクを置かないこと
- [ ] ホスティングの AUP（わいせつ・好ましくない目的等の条項）を確認した
- [ ] ★ ドメインが確定し、レジストラ規約を確認した。NEXT_PUBLIC_SITE_URL を
      実ドメインに差し替えた
- [ ] Supabase の環境変数（URL / anon key / service_role key）が本番用に設定され、
      service_role key がブラウザ側に出ていない
- [ ] Supabase 無料枠の自動停止対策（定期アクセス等）が運用に組み込まれている
- [ ] 移行先ホストを想定済み（凍結・停止時の逃げ先。設定はホスト非依存に保つ）

## 6. 収益まわり（未決事項の解消確認）

- [ ] ★ 送客の契約・歩合条件が確定し、links テーブルに正しいURLが入っている
      （計測ID/リンク発行形態を含む）
- [ ] 単一の送客先・ASPに依存しすぎていない（提携解除リスクの分散）
- [ ] Google AdSense を収益源として前提にしていない（性的文脈は広告制限対象）

## 7. 運営体制・窓口

- [ ] /about の運営者名・所在地・連絡先が実値に差し替わっている（★ 未決の間は公開不可）
- [ ] /removal の削除要請窓口メールが実在するアドレスになっている
- [ ] 削除要請・権利侵害申告への対応フロー（プロバイダ責任制限法）が運用担当に共有されている
- [ ] 年齢配慮の表記（成人向け情報である旨など、ジャンルに応じて必要な注意書き）が
      適切なページに入っている

## 8. 技術チェック

- [ ] `npm run typecheck` が通る
- [ ] `npm run build` が通る
- [ ] スマホ表示で比較表がカード展開になり、横スクロール前提になっていない
- [ ] /go/[id] のクリック記録が clicks に入る（service_role 設定時）
- [ ] DB 未投入の状態でも各ページがエラーで落ちず、空状態の文言が出る
